# Retro — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un plugin `retro` qui relit les sessions Claude Code d'une période, tous repos confondus, et propose puis
applique des améliorations de l'environnement de l'agent.

**Architecture :** un script Python `condense.py`, livré dans le dossier du skill, réduit chaque transcript à ses
signaux (erreurs, répétitions, interruptions, refus, corrections probables) et calcule les lots de lecture. Le
`SKILL.md` décrit le déroulé : cadre des repos, gotchas optionnels, lecture directe ou par sous-agents, filtrage,
restitution, application.

**Tech Stack :** Python 3.12, bibliothèque standard seule (`unittest` pour les tests), Claude Code plugin marketplace.

**Spec :** [`docs/specs/2026-11-21-retro-design.md`](../specs/2026-11-21-retro-design.md). Lire la spec avant chaque
tâche : ce plan fixe les noms, les fichiers et les tests, pas les règles.

## Global Constraints

- Indépendance : aucun import ni appel à un autre skill ou plugin ; `GOTCHAS_DIR` et `superpowers:brainstorming` sont
  optionnels, conditionnés à leur présence.
- Script : Python 3 stdlib uniquement, lancé par `python3 -I`. Pas de dépendance à `~/.claude/skills/daily/`.
- Seuil de lecture directe et taille de lot : `150000` caractères.
- Période par défaut : 7 jours.
- Les condensés vont dans le dossier passé en `--out` (le scratchpad de la session), jamais dans un repo.
- Le dépôt n'a pas encore de tests : les tests vont dans `tests/retro/`, lancés par
  `python3 -m unittest discover -s tests -v` depuis la racine du dépôt. C'est un pattern nouveau pour ce dépôt.
- Branche `feat/retro` depuis `main`. Conventional Commits en anglais, sans trailer `Co-Authored-By` ni ligne
  `Claude-Session`.

## Review Focus

1. Un transcript avec une ligne JSON tronquée (session en cours d'écriture) ne fait pas échouer le script : la ligne
   est ignorée. → Task 1, `test_skips_a_malformed_line`.
2. Un `cwd` qui n'existe plus sur la machine (repo supprimé ou déplacé) est classé « hors repo » sans erreur. →
   Task 2, `test_classifies_a_missing_directory_out_of_repo`.
3. Un condensé plus gros que la taille de lot forme son propre lot, jamais coupé. → Task 2,
   `test_gives_an_oversized_file_its_own_batch`.
4. Un `tool_result` dont `content` est une liste de blocs (et non une chaîne) donne quand même son texte d'erreur. →
   Task 1, `test_reads_an_error_given_as_blocks`.
5. Les transcripts de sous-agents (`<session>/subagents/*.jsonl`) et les entrées `isSidechain` sont ignorés. →
   Task 2, `test_ignores_subagent_transcripts`, et Task 1, `test_ignores_sidechain_entries`.

### Task 1: Extraire les signaux d'une session

**Files:**
- Create: `plugins/retro/skills/retro/scripts/condense.py`
- Test: `tests/retro/test_condense.py`

**Interfaces:**
- Produces, dans `condense.py` :
  - `read_entries(path: Path) -> list[dict]` : une entrée par ligne JSON valide, les lignes invalides ignorées.
  - `extract_signals(entries: list[dict], since: datetime) -> list[Signal]`, entrées de `since` (aware, UTC) et après,
    hors `isSidechain`.
  - `@dataclass Signal(kind: str, time: str, detail: str, before_prompt: str, before_answer: str)`, `kind` parmi
    `tool_error`, `repeat`, `interrupt`, `denial`, `correction` ; `time` en `HH:MM` local.
  - Constantes : `CLIP = 300`, `INPUT_CLIP = 200`, `CORRECTION_MARKERS` (ci-dessous).

Règles de détection (en entrée : les `type` `user` et `assistant` du JSONL) :

- **Message humain** : `user` dont `message.content` est une chaîne, ou une liste sans bloc `tool_result`, non
  `isMeta`, dont le texte ne commence ni par `<system-reminder`, `<local-command`, `<task-notification`,
  `<command-name>`.
- **`interrupt`** : message humain qui commence par `[Request interrupted by user`.
- **`denial`** : bloc `tool_result` `is_error` dont le texte contient `The user doesn't want to proceed`.
- **`tool_error`** : tout autre bloc `tool_result` `is_error`. `detail` = `<nom de l'outil> <entrée résumée> → <début
  de l'erreur>`, l'outil et son entrée retrouvés par `tool_use_id` dans les `tool_use` précédents. Le texte vient de
  `content` chaîne, ou de la concaténation des blocs `text` si c'est une liste.
- **`repeat`** : `tool_use` dont `(name, json.dumps(input, sort_keys=True))` est identique à un `tool_use` antérieur
  de la session dont le résultat était en erreur.
- **`correction`** : message humain qui suit au moins une réponse de l'assistant et dont le texte, en minuscules,
  commence par un marqueur ou en contient un :

  ```python
  CORRECTION_MARKERS = (
      "non,", "non ", "pas ça", "c'est faux", "tu te trompes", "je t'ai dit", "j'ai dit", "arrête", "stop",
      "annule", "reviens", "remets", "revert", "au lieu de", "pourquoi tu", "ne fais pas", "n'ajoute pas",
      "no,", "wrong", "don't", "undo", "that's not",
  )
  ```

- **Contexte** : `before_prompt` = dernier message humain avant le signal, `before_answer` = dernier texte de
  l'assistant avant le signal, chacun tronqué à `CLIP` (espaces normalisés, `…` en fin si coupé). Pour
  `interrupt` et `correction`, `detail` = le message humain tronqué.

### Task 2: Condenser une période et calculer les lots

**Files:**
- Modify: `plugins/retro/skills/retro/scripts/condense.py`
- Test: `tests/retro/test_condense.py`

**Interfaces:**
- Consumes: `read_entries`, `extract_signals`, `Signal` (Task 1).
- Produces, dans `condense.py` :
  - `repo_of(cwd: str | None) -> tuple[str, str]` : `(clé, nom affiché)`. Racine git par
    `git -C <cwd> rev-parse --show-toplevel` ; clé = `git -C <racine> remote get-url origin` si elle existe, sinon la
    racine ; nom affiché = la racine. `cwd` absent, inexistant ou hors git → `("hors repo", "hors repo")`. Résultats
    mis en cache par `cwd`.
  - `batches(sizes: dict[str, list[tuple[str, int]]], limit: int = 150000) -> list[list[str]]` : `sizes` = repo →
    liste de `(fichier, nb de caractères)`. Remplissage glouton dans l'ordre des repos puis des fichiers ; un repo qui
    tient dans le lot courant y reste entier ; un fichier n'est jamais coupé ; un fichier plus gros que `limit` forme
    son propre lot.
  - `main(argv: list[str] | None = None) -> int`, CLI :
    `condense.py --since YYYY-MM-DD --out DIR [--projects DIR] [--limit 150000]`. `--projects` vaut
    `~/.claude/projects` par défaut. `since` = minuit local de la date.

Comportement de `main` :

- Lit `<projects>/*/*.jsonl` (un seul niveau : les `subagents/` sont exclus) dont la date de modification est
  postérieure à `since`.
- Pour chaque session ayant au moins une entrée dans la période : `repo_of` du premier `cwd` de la période ; si elle a
  des signaux, écrit `<out>/<repo slug>--<session id>.txt` :

  ```
  session <id> · <repo affiché> · <branche> · <titre ai-title ou ->
  <première date YYYY-MM-DD HH:MM> → <dernière date HH:MM> · <n> tours

  [HH:MM] <kind>: <detail>
    avant · humain: <before_prompt>
    avant · claude: <before_answer>
  ```

- Imprime sur stdout un JSON :

  ```json
  {"since": "YYYY-MM-DD", "limit": 150000, "sessions": 0, "sessions_with_signals": 0, "total_chars": 0,
   "repos": [{"key": "...", "name": "...", "sessions": 0, "files": ["..."], "chars": 0}],
   "batches": [["..."]]}
  ```

  `batches` ne contient qu'un lot quand `total_chars <= limit`.

- [ ] **Step 1: Écrire les tests qui échouent**, classe `CondenseTest`, avec un `--projects` temporaire et des repos
  git créés par `git init` dans un dossier temporaire :

  - `test_writes_a_file_only_for_a_session_with_signals` : deux sessions du même repo, une avec une erreur → un
    fichier, `sessions == 2`, `sessions_with_signals == 1`.
  - `test_groups_two_clones_of_the_same_remote` : deux dépôts git avec le même `origin` → une seule entrée dans
    `repos`.
  - `test_classifies_a_missing_directory_out_of_repo` : `cwd` inexistant → repo `hors repo`.
  - `test_ignores_subagent_transcripts` : un `<projet>/<session>/subagents/agent-x.jsonl` avec une erreur → aucun
    fichier.
  - `test_ignores_sessions_older_than_the_period` : session dont les entrées sont antérieures à `--since` → absente de
    `sessions`.
  - `test_keeps_one_batch_under_the_limit` : `batches({"a": [("a1", 10)], "b": [("b1", 10)]}, limit=100)` →
    `[["a1", "b1"]]`.
  - `test_keeps_a_repo_together_when_it_fits` : `batches({"a": [("a1", 60)], "b": [("b1", 30), ("b2", 30)]},
    limit=100)` → `[["a1"], ["b1", "b2"]]`.
  - `test_gives_an_oversized_file_its_own_batch` : `batches({"a": [("a1", 250), ("a2", 10)]}, limit=100)` →
    `[["a1"], ["a2"]]`.
